# 多市场、PIT 资料、真实权益与逐笔回放

本次新增的是可运行的现金股票回测路径：CN（人民币）、US（美元）、KR（韩元）。同一份策略可用 `market="CN" / "US" / "KR"` 切换；对应行情和证券资料也必须切换，A 股行情不能变成美股行情。

先运行：

```powershell
cd .
python examples/market_switch.py
```

脚本会生成三个市场的 HTML、JSON 资料模板、组合人民币估值和逐笔队列流水。**样例全是合成数据；零手续费、10% 分红预扣税只是示例参数，不是三个国家的法定税率。**

也可打开 `notebooks/多市场与逐笔回放.ipynb`，在标明的策略格粘贴 Python 代码，然后依次运行。

## 策略入口

```python
import qbt

d = qbt.load_market_csv("bars.csv", "US")
ref = qbt.ReferenceData.from_json("reference.json")

def strategy(ctx):
    # 在这里替换成你的选股、排序和目标持仓代码。
    return ctx.long(ctx.universe(min_listed=60).top(-ctx.ret(5), 10))

r = qbt.run(d, strategy, market="US", reference_data=ref, capital=100_000)
qbt.report(r, path="reports/my_us_run")
```

`top` 选择得分最大的股票，上例对五日收益取负号以选择跌幅较大的股票。目标组合与直接订单两个入口都支持同样的市场参数：

```python
def orders(ctx):
    if ctx.T == 1:
        ctx.order("AAPL", 10, limit_price=100.00, tif="GTC")

r = qbt.run_orders(d, orders, market="US", reference_data=ref, capital=100_000)
```

命令行：

```powershell
python run_strategy.py --strategy my_strategy.py:strategy --market US --reference reference.json --data bars.csv --start 2024-01-02 --end 2024-12-31 --capital 100000 --output reports/us --health
```

## 行情与资料格式

`bars.csv` 为长表，列为：

```text
timestamp,code,currency,open,high,low,close,amount,trades,cumadj
2024-03-08,AAPL,USD,170,172,169,171,1000000000,100000,1
```

`amount` 是当地货币成交额，不能把成交股数填进来。`trades` 缺失时保留 NaN，不伪造成交笔数；显式权益模式可省略 `cumadj`，由股份事件重建价格基准。重复日期/股票组合、币种混用会报错。

`qbt.from_market_arrays` 接受带时区的 ISO 时间并显式转换为目标市场本地时间；无时区值表示调用者已经提供当地时间。原有 `Dataset.from_arrays` 仍拒绝含糊的带时区输入。内部时间标签保持无时区，跨市场合并时才转换为 UTC。

JSON 清单字段可直接放数组，也可用相对于 JSON 文件的 CSV 路径：

| 字段 | 内容 |
|---|---|
| `profile` | CN、US、KR |
| `sessions` | date、open、close、可选 break_start / break_end，支持午休、提前收市、特殊开市 |
| `settlement_sessions` | 实际交割营业日列表；与交易日不同的银行假日也应反映 |
| `securities` | code、currency、listing_date、known_at，可选 board、delisting_date、listed_sessions_at_start |
| `records` | code、field、value、effective_from、known_at，可选 effective_until |
| `actions` | 除权、分红、股份交付及税率，见下文 |
| `settlements` | 终止日、回收价格、实际支付日及预扣税 |
| `taxes` | 后续真实税款补扣/核定，date、code、amount、known_at、reason |
| `fees` | 生效和失效日期、券商佣金、最低收费、买卖税费、按股收费及上限 |

`records.field` 支持 `st`、`suspended`、`no_limit`、`reference`、`band`、`limit_up`、`limit_down`。状态同时按“何时生效”和“何时已知”筛选，后来发布的更正不重写过去。日频以开盘前为知悉截止，日内以该行时间为截止。

严格模式默认开启：每只股票必须有明确的停牌状态基线，CN 还需 ST 基线；明确填 false 表示资料确认了正常状态。KR 必须提供每日官方上下限价格，避免用 30% 粗算和错误取整模拟真实限价；IPO 特殊价格范围也可通过这两个字段输入。CN 新股早期交易日必须明确提供无限制状态或官方价格范围。

上市年龄使用实际上市日期。若上市早于所提供日历，只能得到保守下界；要得到准确年龄，应扩展日历或填写有资料依据的 `listed_sessions_at_start`。`delisting_date` 若写入证券基线，也必须在该基线的 `known_at` 已知；事后才知道的终止事件放在带知悉时间的 `settlements`。

可用 `qbt.market_profile("US").sessions(start, end)` 调用已安装的 `exchange_calendars` 适配器。其版本和来源会记录；它不是交易所实时公告。超出覆盖范围会报错，例如当前安装版 XSHG 日历无法提供 2026 全年，不能外推工作日冒充交易日。

## 账户与规则

| 规则 | CN | US | KR |
|---|---|---|---|
| 股份当日转售 | T+1 | 已交割资金买入的股份可当日卖 | 可当日卖 |
| 卖出款购买力 | 交易日可再买，交割前不可提取 | 保守模型：交割后才可再买或提取 | 保守模型：交割后才可再买或提取 |
| 普通现金交易交割 | T+1 配置 | 2024-05-28 前 T+2，此后 T+1 | T+2 |
| 数量 | 主板/创业板整手、科创板/北交所单独规则 | 整股 | 整股 |
| 价格单位 | 0.01 | ≥1 美元默认 0.01，低于 1 默认 0.0001 | 2023-01-25 起的分档 tick |

这是保守的现金账户，不是券商保证金账户。未交割卖出款仍属于账户资产，但不全部属于购买力；结果单独给出 `unsettled_cash` 和 `withdrawable_cash`。未提供日历尾部交割日时，款项继续标记未交割，不猜一个到账日。

KR 普通股 tick 档为：低于 2,000 韩元为 1；2,000/5,000/20,000/50,000/200,000/500,000 档分别为 5/10/50/100/500/1,000。更早制度要求传入有日期的 `tick_rule`。US 2027 年 11 月之后也要求显式规则，避免把尚可能变化的改革永久写死。

CN 主板 ST 板幅按日期分段：2026-07-06 前为 5%，此后为 10%；科创板、创业板仍按各自规则。官方上下限和无限制状态优先于粗略的基准板幅。

`fees` 的 `effective_from` / `effective_until` 必须覆盖回测日；不能把最新费率无限延伸到历史。支持 `commission`、`minimum`、`buy_tax`、`sell_tax`、`slippage_bps`、`buy_per_share`、`sell_per_share`、相应的 `*_per_share_cap`。订单分批成交按实际累计股数和金额计算增量费用。券商、账户类型和豁免不同，因此 US/KR 不默认填一张零费用表。

US 可通过逐时状态输入停牌和价格范围；触及输入的 LULD 上限不自动解释成 A 股“涨停买不到”。没有这些资料时，不声称已经重建 LULD、竞价、熔断、隐藏订单、跨场所路由等全部制度。

## 分红、登记、税和终止分配

显式资料模式把价格和收益区分开：原始 OHLC 用于交易，股份比例形成拆股价格基准；现金分红不会自动增加股数。`ctx.ret / vol / adj` 使用包含净现金分配的总收益指数，该指数不是可以下单的价格。`ctx.open / close_raw` 保留当地原始价格语义。

总收益指数按逐期收益连乘，是用于信号/基准的再投资指标；真实现金账户仍按支付日到账，两者不保证在除息后的所有时刻收益完全相同。

分红首先计应收，实际支付日才进入现金。`withholding_rate` 是调用者依据投资者身份、税收协定及实际券商资料填写的参数；不能按国别猜一个统一股息税。严格模式要求现金权益显式填写税率，免税或使用毛额也要明确填 0；增股须明确提供 `share_date`，不默认立即可卖。`TaxAssessment` 支持卖出后发生的补扣等后续税款：立即减少净资产，现金不足部分列为应付税款，不能透支现金后继续满仓买入。权益税款单列，不重复加入已经扣过的交易费用。

普通事件的 `entitlement_basis="ex_previous_close"` 取除息前持仓作为经济权益资格；`record_date` 保留法律登记日，不把 T+1/T+2 市场的登记日持仓直接当成交易日持仓。特殊现金权利可显式选择 `record_close`，系统保存指定登记收盘时的股数，之后卖出不抹掉已经取得的权益。此模式必须登记日在除息之前，且只支持现金分配；复杂 due-bill 等安排需要提供经过供应商核对的权益事件，不能自动推断。

终止日清除股份、确认实际回收权利；`pay_date` 晚于终止日时列应收，不提前成为现金。实际回收为零可以明确填写，未知回收不能填成零。

止损按持仓获得的分配和拆股基准计算，避免单纯除息/拆股触发虚假止损；加仓摊薄历史分红也不会单独造成追踪回撤。总收益因子和现金事件不会各记一遍分红。输入因子有跳变却缺少相应事件时会报错；`factor_mode="validate_split"` 可逐格校验明确声明为拆股口径的源因子。普通 `derive` 模式信任显式事件，原始混合复权因子不再兼任交易账本规则。

旧的不带 `ReferenceData` 的课程入口保留原有 `reinvest` 近似，旧数据缺失的真实权益不会凭空补全。需要以上新口径时，应显式加载资料清单。

## 逐笔队列

`qbt.run_l3` / `qbt.load_l3_csv` 是独立入口，使用 `timestamp,sequence,kind,code,order_id,side,price,quantity`。`side` 是被动订单方向，`kind` 是 add / cancel / execute；add 必须表示真实进入显示队列的挂单，供应商原始消息需要先归一化。

模型记录前方订单，成交和撤单分别减少前方数量；前面消耗完后，后续成交证据才可以分给自己的订单。同一成交量不能被多个模拟订单重复使用。新单/撤单均有延迟，同刻市场消息先发生。主动订单对同一显示流动性只消费一次。序列缺口、缺少订单历史、非 FIFO 的成交会中止，不猜测跳过的数据。

支持每笔成交的订单、价格、数量、费用、时间和证据标识，结果包含输入消息哈希和策略代码身份。初始快照可转成 add 消息并设置 `warmup_events`，快照装完前不调用策略，避免暴露半本订单簿。证据结束时未决订单标为 `EVIDENCE_ENDED`，不伪称已经被交易所撤销或到期。`admission(timestamp, request)` 可注入当时已知的停牌、权限和每日限价等申报校验。

当前为单会话、显示订单、FIFO 的影子回放。它保留历史市场消息，模拟自己的订单插入，不能证明历史上一定成交，也不会模拟其他人对你的订单作出反应。跨日权益/资金交割使用日线/分钟引擎；隐藏流动性、竞价、比例分配、跨场所路由和市场响应需要相应数据及其他执行模型。日线不会自动生成这些逐笔数据。

## 汇率与复现

`FXRates` 要求带时区的报价和公布时间，取估值时已公布且未过期的汇率；不能用未来汇率回填。`aggregate_results` 按 UTC 时点选各市场最近已经完成的估值，再换算到基准货币。首个估值尚不存在会报错；不能把稍后美国收盘价拿来估亚洲上午的组合。

组合是分别出资的独立账户，汇总不意味着账户间可以互相融资，也没有隐式自动换汇。跨账户调拨和真实换汇交割需显式的资金流程。

新接口仍是研究回测，没有实盘下单。真实 US/KR 行情、历史证券状态、权益、税款和 L3 数据必须由数据源提供，本次没有购买、下载或伪造完整商业历史库。
