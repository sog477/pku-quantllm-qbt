# 开放式引擎 v0.3：目标组合与直接委托

本次扩展新增订单入口，并将调度时钟、资产申报/结算规则和账户规则从原有日频主循环中拆出。默认配置继续是 A 股日频现金账户；旧策略不需要迁移。

## 两种并列入口

```python
# 目标式：声明组合，交给撮合器分配股数。
r = qbt.run(data, factor_strategy)
r = qbt.run_events(data, daily_target_strategy)

# 订单式：自己管理委托生命周期。
r = qbt.run_orders(data, order_strategy)
```

目标入口保留自动再平衡、缓冲与风控。订单入口不自动改写用户订单，也不会自动插入目标模式的止损单；策略可自行下止损退出单、撤销旧单并查询实际成交。两条调度路径共用 Account、Broker 的容量/成本组件、资产规则、账户规则与时钟，订单式执行由 OrderBook 管理。

```python
class Strategy:
    def reset(self):
        self.pending = None
        self.waited = 0

    def __call__(self, ctx):
        if self.pending is None:
            price = float(ctx.close_raw()[-1, 0]) * .98
            self.pending = ctx.order(ctx.codes[0], 100, side="buy",
                                     limit_price=price, tif="GTC")
        else:
            self.waited += 1
            order = ctx.get_order(self.pending)
            if self.waited >= 5 and order.status in ("OPEN", "PARTIAL"):
                ctx.cancel(self.pending)

r = qbt.run_orders(data, Strategy())
```

回调仅提供截至执行行之前的特征切片：`ctx.now` 是最近已完成行情时间，`ctx.execution_time` 是已知的下一调度时间。`ctx.portfolio` 是前一收盘快照；`ctx.orders(active_only=True)` 查询未完成委托。输入行情对象与外部变量仍由用户代码控制，这不是防作弊沙箱。

也可返回 `OrderRequest(...)`、`Cancel(id)` 或它们的列表。命令式回调返回 `None` 即可；`HOLD` 也表示不新增命令。目标组合请使用 `run/run_events`，不要在订单回调中返回 Target。

## 订单生命周期

订单类型为市价或限价（`limit_price=None` 表示市价）。有效期包括 DAY、GTC、GTD；GTD 必须提供 `valid_until`。日期型截止时间包含整个日期，时间戳型截止时间包含对应时刻。若新单截止时间已经早于首次执行时刻，立即过期，不允许成交。

状态为 OPEN、PARTIAL、FILLED、CANCELED、EXPIRED、REJECTED。撤销/到期保留已经成交的部分。未知代码或不符合资产申报数量的委托被拒绝；资金、可卖数量或容量暂时不足时保留剩余委托，等待后续事件或到期。

内置订单簿采用 FIFO，**不预留现金或股份**。多笔买单按顺序竞争实际可用资金，不会透支；卖单实际成交时检查可卖数量。买卖各自共享该行情行的容量，而不是每笔订单都重新获得一份容量。同一订单在同一会话分批成交按累计成交额计算费用，最低佣金不会每个部分成交重复收取；跨会话重新计算。

申报数量与部分成交数量要区分：一笔合法的200股普通股票委托，可以部分成交110股、再成交90股；直接申报110股则会被默认 A 股规则拒绝。目标式入口仍按合法申报单位生成每次调仓数量。

```python
for order in r.orders:
    print(order.id, order.status, order.filled, order.remaining, order.average_price)

r.order_events  # 状态、原因、时间戳
r.order_fills   # 订单ID、价格、数量、费用、开盘/收盘阶段
r.trades       # 兼容原有报告/指标的成交流水
qbt.report(r, path="reports")  # 新增订单生命周期表，展示前100笔；Result保留完整记录
```

默认 `OpenExecution` 只在下一调度 bar 的开盘尝试：买单开盘价不高于限价、卖单开盘价不低于限价时才成交，并采用较优的开盘价。不会根据当天最低价假装在开盘就知道能买到。

可选 `BarTouchExecution`：开盘未成交的限价单若在该 bar 的 OHLC 中触价，在 bar 结束后记账。收盘卖出款不能用于同 bar 的开盘买入；OHLC 无法证明触价先后或盘口排队，所以该模型是明确的乐观假设，报告会标注。自定义执行模型实现 `phases`、`description`、`price(request, ds, index, phase)`；成交价必须有限、为正且不违反限价。

公司行动发生时，默认取消受影响的未成交委托，不猜测挂单价格和数量如何调整。已知清算事件后相关挂单也取消。公司行动数据与默认再投资近似的边界继续适用。

## 时间戳与交易会话

```python
bars = qbt.BarDataset.from_arrays(
    timestamps, codes, previous_close=previous_session_close,
    open=open_array, high=high_array, low=low_array, close=close_array,
    amt=amount_array, num_trades=trades_array, cumadj=factor_array)

r = qbt.run_orders(bars, strategy,
    clock=qbt.BarClock(periods_per_year=242 * 240))
```

`BarDataset` 保留完整时间戳，不会把一天内多个 bar 压成同一日期。`periods_per_year` 必须按自己的数据频率和市场日历显式配置；指标和因子波动率使用该参数。不同估值频率的结果不能直接 compare，须先统一时钟。

默认 `DailyClock` 要求每天最多一行。`BarClock` 每行产生一个执行事件，策略看到此前完成的行。`stride` 可减少调度机会，但也会跳过这些行的撮合，不等同于“只降低调仓频率、订单仍每分钟撮合”；希望后者，应保持逐 bar 时钟，只在策略中按自己的日程新增订单。

容量的 `adv_window` 按输入行情行计数：分钟数据中默认20代表过去20根bar，不能理解为20个交易日。当前bar成交额仍只是事后成交上界。需要按日ADV或其他流动性模型时，替换 Broker.capacity_amount。

时钟协议：`periods_per_year`、`events(ds,start,end)`、`is_session_end(ds,index)`。事件包含行情行号、当前与前一时间戳、`new_session` 和 `session`。可继承 BarClock 覆盖 `session_key(timestamp)`，例如让跨午夜的行情属于同一个会话。T+1 根据会话边界解冻，而不是每过一个 bar 就解冻；DAY 有效期也按会话结束处理。

分钟 A 股的涨跌停参考价沿用上一交易日收盘，并按公司行动因子修正，不随每分钟收盘漂移。首个会话可通过 `previous_close` 或 MarketMetadata.reference 提供真实参考价；没有参考价时默认价格限制资产不能成交。日内数据不使用“过去120根分钟bar”冒充ST历史，真实ST需显式元数据。无价格限制的现金资产规则只要求有效报价，不强制提供涨跌停参考价。

## 独立资产与账户规则

```python
assets = qbt.CashAssetRules(
    minimum=[100, 1], step=[100, 1],
    settlement_days=[1, 0], price_limits=[True, False])

r = qbt.run_orders(bars, strategy, asset_rules=assets,
                  account_rules=qbt.CashAccountRules(), clock=clock)
```

这只是两种合成现金资产的研究配置，不代表所有ETF或其他市场的真实规则。默认 `AStockRules` 提供普通股票与科创板数量规则。

资产组件 `bind(ds)` 返回按证券对齐的步骤、最小申报、结算与限价规则；提供 `round_buy/round_sell/can_buy/can_sell`。内置规则支持每只证券的 T+0/T+1。账户组件负责 `validate_gross`、`start_bar`、`buying_power`、`sellable`、`buy/sell`、`equity`、`check`。上述参数在目标入口和订单入口均可传入。原有 account_factory、broker_factory 与 costs 继续可用。

默认账户仍只做多、不融资、使用整数份额。此次已把策略空间的约束移到规则接口，但**没有宣称已实现融券、期货保证金、多币种或分数份额账本**。这些需要配套账户、规则与结算实现，不能只把 max_gross 改大。也没有实盘订单、交易所队列或逐笔撮合。
